Edit & Run Guide

Use the authored Unity scene for layout work. Preserve the latest local edits before fetching or switching revisions.

1. Open the correct scene

Use the existing COD Unity project with Unity 6000.6.5f1. Open Assets/COD/Editable/Authoring/CODEditableGame.unity. Do not create a replacement project or regenerate the Authoring directory. The older Assets/COD/GameGenerated/CODGame.unity is a rollback scene.

The game repository is private: SheesshhOfficial/Vopa.LearningGarden. Its published development baseline is cod/visual-preview at 1400f1f; latest local Pip/layout work is not yet committed. This public workspace contains documentation, not the private Unity project.

2. Edit persistent layouts

  1. Stop Play before making edits that must persist.
  2. Select a named screen instance in the authored scene or open its prefab under Assets/COD/Editable/Authoring/Prefabs/.
  3. Edit RectTransform position, size and anchors; edit Text, Image and visual components for styling.
  4. Keep serialized view references and named content slots intact. Save the scene/prefab and review intentional instance overrides.
  5. Enter Play, visit the screen, return Home and confirm the layout still looks correct; stop Play and confirm your saved placement remains.

Normal Unity edits made only during Play do not persist. The create-once builder must never be used to overwrite designer-owned screens.

3. Know which system owns which fields

  • Designer: layout, static labels, type styling, art composition and anchor placement.
  • Presenter: current prompt, answer labels, progress, visibility and button availability.
  • Motion components: designated nested Visual children, not the designer’s root anchor.
  • GameSession / QuestionGenerator: rules and generated questions; do not implement those by rearranging UI objects.
  • Local save: player progress/settings. Validation must use isolated progress rather than overwrite the owner’s data.

The theme supplies authoring defaults; changing it is not a promise that every already-authored component will restyle automatically. The in-project guide is Assets/Editor/CODEditable/DESIGNER_GUIDE.md.

4. Review the demo flow

  1. Home → Map → first house → Greeting.
  2. Try one wrong answer and its hint, then complete the three questions.
  3. Review the envelope/hearts, onward travel and all five activities.
  4. Revisit a delivered house and confirm no duplicate first-delivery reward.
  5. Check Settings/reduced motion and Pip’s Greeting animation.

Automated Editor evidence supports this flow, but a human visual/input pass is still necessary. The client demo was prepared; its outcome has not been confirmed.

5. Safe next checkpoint

Inspect and preserve local changes first. Do not reset, clean, regenerate authored screens or blindly replace files to obtain a clean checkout. Keep native execution to small pinned jobs with sanitized summaries, and distinguish product-source publication from generated evidence. No new native command or tool installation is required by this documentation update.
