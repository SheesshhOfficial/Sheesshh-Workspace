Game & UI plan

One coherent, playful fort adventure, built from editable screens rather than runtime-reconstructed layouts.

UI polish now requested

  • Use consistent button shapes, panel treatments, headings, labels, spacing and icon sizes across Home, Explore, fort/game selection, stages, instructions, gameplay and results.
  • Give every page one obvious primary action. Keep secondary navigation smaller but reachable.
  • Use the supplied Tarang references for the visual language and preserve game-specific art. Backgrounds should support, not compete with, questions and controls.
  • Keep text readable on short portrait screens, touch targets comfortably sized, and foreground panels clear of the playable area.
  • Represent locked, current and completed stages with icons and text as well as color.
  • Use restrained feedback and motion. Decorative birds must not distract from the playable character.

These are implementation goals for the current pass, not a claim that the redesigned screens already exist or have passed review.

Question and attempt rules

  1. Start or retry with three lives and zero correct answers for the current attempt.
  2. Show first-use instructions. Help/instructions pause the question timer and resume safely.
  3. Start the ten-second question timer after the relevant narration finishes.
  4. A correct answer increments cumulative stage progress. A wrong answer or timeout loses one life and selects a new question.
  5. Three correct answers complete the stage. Zero lives shows retry; retry preserves earlier completed stages.
  6. Protect against double taps, timeout/answer races, repeated popup closure and duplicate rewards.

Game-specific composition

MathFly

Retain the purple playable bird, right-side pillar gap, game-specific day/night artwork and four colored bottom answers in a 2 × 2 layout. Answers drive bird motion; there is no collision penalty. Select day/night once per attempt. Four-stage selection uses castle-style nodes.

NumberLineJump

Ask before/after number questions with distinct choices and a readable number line. Share progression, attempt and narration rules without forcing MathFly artwork into this game.

Exact numeric ranges, distractor difficulty and curriculum alignment still need content confirmation. Do not invent the six remaining game names.

Navigation, saves and rewards

Home Play finds the earliest unfinished curriculum stage even after replaying completed content. Only Fort 1 is initially available. All eight games would be required for a fort flag; the two-game demo must not award full-fort completion.

Use a single anonymous local profile. Persist stage completion, stars and stickers without duplicate rewards. Keep sound, help and future language controls separate from destructive progress reset. Cloud accounts, leaderboards and backend enforcement are not part of the current implementation scope.

Editable production workflow

  1. Inspect the actual scene and relevant prefab before making changes; preserve owner edits.
  2. Commit or back up the scoped starting state. Edit authored page prefabs and reusable UI assets.
  3. Run import and applicable tests against the final changes.
  4. Inspect actual rendered screens at multiple portrait sizes and test repeated navigation, answers, help, retry and results.
  5. Publish the reviewed scoped changes, pull them into the main project, and rebuild the preview only after verification.

Keep essential native build/test support, but remove obsolete runner-specific setup only after checking dependencies and preserving recovery. No separate runner clone should be presented as the user's main editable project.

Content and presentation

English text and spoken explanations are current scope. Keep text/audio keys separate from layouts for a future Marathi setting. Narration quality, missing-audio fallback, replay timing and browser audio unlock require real runtime checks. Learner age, syllabus and final wording remain unconfirmed.

Public project documentation. Private game source and client production assets remain in the private game repository. Implementation, test results and visual acceptance are separate.
